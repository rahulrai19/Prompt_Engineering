# Few-Shot Prompting

## Concept
A handful of input/output examples locks in a format more reliably than
describing the format in words. The pattern itself becomes the spec.

## Why it matters for developers
Useful anywhere you need consistent structured output across many calls —
e.g., turning arbitrary error strings, log lines, or free-text into a
fixed shape your app can parse without per-case special handling.

## Test Prompt
```
Convert each error message into a structured error object following the pattern below.

Input: "File not found"
Output: {"code": "ERR_FILE_NOT_FOUND", "message": "File not found", "hint": "Check that the file path exists and is spelled correctly."}

Input: "Invalid API key"
Output: {"code": "ERR_INVALID_API_KEY", "message": "Invalid API key", "hint": "Verify your API key is correct and has not expired."}

Input: "Request timed out"
Output: {"code": "ERR_REQUEST_TIMEOUT", "message": "Request timed out", "hint": "Check your network connection or increase the timeout duration."}

Input: "Permission denied"
Output:
```

## What the 3 examples pin down (without stating any rule explicitly)
- `code`: `ERR_` prefix + SCREAMING_SNAKE_CASE derived from the message
- `message`: copied verbatim from the input
- `hint`: one actionable sentence, not a restatement of the error
