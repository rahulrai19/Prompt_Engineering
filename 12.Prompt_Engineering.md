# Prompt Engineering — Types, Capabilities & Use Cases

A reference taxonomy of named prompting techniques, organized by what each
one controls. This sits alongside the 11-phase hands-on plan as a quick
lookup for "which technique do I reach for."

## 1. By Number of Examples Given

| Type | What it is | Capability unlocked | Best developer use case |
|------|-----------|----------------------|--------------------------|
| **Zero-shot** | Ask directly, no examples | Fast, cheap, works for tasks the model already generalizes well | Well-known tasks: "write a function to reverse a string" |
| **One-shot** | Exactly one example | Pins down a specific format/style with minimal token cost | Quick format demo when the pattern is simple |
| **Few-shot** | 2–5+ examples | Locks in consistent structure, tone, or edge-case handling across many calls | Turning error strings into structured objects (Phase 4) |
| **Many-shot** | Dozens+ examples | Approaches fine-tuning-level consistency without training a model | High-volume classification/formatting pipelines with a long context budget |

## 2. By Reasoning Strategy

| Type | What it is | Capability unlocked | Best use case |
|------|-----------|----------------------|----------------|
| **Chain-of-thought (CoT)** | Explicitly ask for step-by-step reasoning before the answer | Better accuracy on multi-step logic | Debugging (Phase 5), math, algorithm design |
| **Zero-shot CoT** | Just add "let's think step by step" with no examples | Same benefit, less setup | Quick reasoning boost on a one-off question |
| **Self-consistency** | Run the same reasoning prompt multiple times, take the majority answer | Reduces variance on ambiguous or hard problems | High-stakes single answers where one bad sample is costly |
| **Tree-of-thought** | Model explores multiple reasoning branches, evaluates them, can backtrack | Handles problems with dead ends or multiple candidate solutions | Complex planning, puzzle-solving, architecture decisions with trade-offs |
| **ReAct (Reason + Act)** | Interleaves reasoning with tool calls: think → act → observe → repeat | Foundation of agentic systems | An agent that searches, reads results, and reasons about what to do next |

## 3. By Structure and Framing

| Type | What it is | Capability unlocked | Best use case |
|------|-----------|----------------------|----------------|
| **Role/persona prompting** | "You are a senior security engineer..." | Steers vocabulary, priorities, and depth of the response | Getting domain-specific review focus (security vs. UX vs. performance) |
| **System prompting** | Instructions set once, outside the conversation flow | Persistent behavior across an entire session/app | Setting house style or constraints for every response in a product |
| **Structured/XML-tagged prompting** | Tags separate instructions from data (Phase 3) | Prevents instruction/data confusion, resists injection | Any pipeline handling untrusted or user-supplied content |
| **Template/schema-constrained prompting** | Explicit output schema (Phase 6) | Guarantees parseable, consistent structure | API responses, structured data extraction |

## 4. By Workflow Architecture

| Type | What it is | Capability unlocked | Best use case |
|------|-----------|----------------------|----------------|
| **Prompt chaining** | Output of one prompt feeds the next (Phase 9) | Breaks a big task into narrow, reliable steps | Generate → review → refine pipelines |
| **Meta-prompting** | Ask a model to write or improve a prompt | Bootstraps and iterates on your own prompt library | Automatically refining a prompt after seeing failure cases |
| **Retrieval-augmented prompting (RAG)** | Inject retrieved documents/context into the prompt at request time | Grounds answers in current or private data the model wasn't trained on | Q&A over your own codebase, docs, or knowledge base |
| **Tool-use / function-calling prompting** | Model decides when to invoke defined tools (Phase 8) | Extends the model beyond text generation into real actions | Agents that query APIs, run code, or fetch live data |

## Quick Capability Map — "What Unlocks What"

- **Need consistent format across many calls?** → Few-shot or schema-constrained prompting
- **Need correctness on multi-step logic?** → Chain-of-thought, and self-consistency if it's high-stakes
- **Need the model to explore trade-offs before deciding?** → Tree-of-thought
- **Need it to act on the world, not just answer?** → Tool use + ReAct
- **Need it grounded in your actual data, not training data?** → RAG
- **Need to resist malicious/untrusted input?** → Structured/XML-tagged prompting
- **Need a multi-step pipeline instead of one giant ask?** → Prompt chaining
