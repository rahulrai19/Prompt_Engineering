#  Output Control & Structured Output

## Concept
Once a response is parsed in code rather than read by a person, any stray
prose or markdown fence breaks `JSON.parse()`. Explicit constraints on
format matter as much as constraints on content.

## Why it matters for developers
This is the difference between a demo and something you can actually wire
into a pipeline. A model that "usually" returns clean JSON isn't good
enough once failures happen in production silently.

## Test Prompts

### Prompt A — loose ask
```
Give me a JSON description of a REST endpoint for creating a new user account.
```

### Prompt B — strict constraint
```
Return ONLY a valid JSON object — no markdown code fences, no explanation,
no text outside the JSON — describing a REST endpoint for creating a new
user account. Use exactly this schema:
{ "method": string, "path": string, "requestBody": object, "responses": { "201": object, "400": object, "409": object } }
```

## Note
Most major platforms also expose a dedicated structured-output/JSON mode
as an actual API parameter (schema-enforced server-side), which is more
reliable in production than prompting alone. Worth checking each
platform's current docs for the exact parameter name.
