# Chain-of-Thought / Reasoning Prompts

## Concept
Asking a model to reason through a problem before answering helps most on
problems with several interacting rules, where jumping straight to an
answer risks skipping a step.

## Why it matters for developers
Multi-step logic bugs, ordering/timing questions (event loops, concurrency),
and anything with several rules that combine are exactly where careless
direct answers go wrong. Forcing a trace-through catches mistakes before
they reach the final answer.

## Test Puzzle
```javascript
console.log('A');

setTimeout(() => console.log('B'), 0);

Promise.resolve().then(() => {
  console.log('C');
  Promise.resolve().then(() => console.log('D'));
});

(async () => {
  console.log('E');
  await null;
  console.log('F');
})();

console.log('G');
```

## Test Prompts

### Prompt A — direct answer
```
What order do these console.log statements print in?
```

### Prompt B — reasoning first
```
Walk through this step by step: first the synchronous execution order, then
the microtask queue (in the order tasks get added to it), then macrotasks.
Only give the final letter order after you've traced through all three.
```

## Correct Answer
`A, E, G, C, F, D, B`

Key traps: the async IIFE runs synchronously up to its first `await`; the
`D` task gets queued *behind* the already-waiting `F` continuation, not
right after `C`.
