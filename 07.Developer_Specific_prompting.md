#  Developer-Specific Prompting Patterns

## Concept
Code generation, debugging, and review each need a different shape of
information. For debugging specifically: a minimal repro with the exact
expected-vs-actual output removes ambiguity; dumping a whole file with a
vague "something's broken" forces broad review and produces a hedged,
less certain answer even when the fix ends up the same.

## Why it matters for developers
Less signal-to-noise means more tokens spent, slower answers, and lower
confidence that the fix actually addresses the symptom you're seeing —
not just "a" bug the model happened to notice.

## The Bug
```python
def flatten(nested_list):
    result = []
    for item in nested_list:
        if isinstance(item, list):
            result.append(flatten(item))
        else:
            result.append(item)
    return result
```
Fix: `result.append(flatten(item))` → `result.extend(flatten(item))`
(appending re-nests the recursive result instead of merging it).

## Test Prompts

### Prompt A — minimal repro, exact symptom
```
This function should flatten a nested list but doesn't:

[flatten function above]

Input: flatten([1, [2, 3, [4, 5]], 6])
Expected: [1, 2, 3, 4, 5, 6]
Actual:   [1, [2, 3, [4, 5]], 6]

What's wrong and how do I fix it?
```

### Prompt B — whole file, vague symptom
```
Here's my utils.py file. Something in here has a bug, can you find it and fix it?

[flatten, reverse_string, is_palindrome, sum_of_digits, find_duplicates —
5 functions, no error message, no expected/actual output given]
```

## Results Log
